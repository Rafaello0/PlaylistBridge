Privacy Policy

Updated: November 11, 2026 · PlaylistBridge Windows desktop application

This Privacy Policy describes the data accessed, processed, transmitted, and stored when you use the PlaylistBridge Windows desktop application to connect your Spotify and YouTube accounts and transfer playlist entries. PlaylistBridge is an independent utility and is not affiliated with Spotify, Google, or YouTube.

1. Purpose and API services

PlaylistBridge uses Spotify's official APIs and YouTube API Services (YouTube Data API v3) to read authorized playlist information, find matching YouTube videos, and create or modify YouTube playlists when requested by the user. PlaylistBridge transfers references and metadata, not music or video files. Features requiring access to a user's account use OAuth authorization through the respective service's official sign-in pages.

2. Information the application accesses and uses

The information processed depends on which services and features you authorize and use:

  • Google/YouTube account and channel information: the name and ID of the authorized YouTube channel, authorized playlists and their IDs, playlist titles, video IDs and titles, playlist items and related metadata returned by YouTube Data API v3. The application uses this information to identify the selected destination and show or modify the user's playlists.
  • YouTube search and matching information: search queries, YouTube video search results, video IDs and titles, selected matches, and source-to-destination associations. These support song matching, user review, avoiding duplicate entries, and resuming transfers.
  • Spotify account and music-library information: playlists, saved or top tracks when the corresponding features are selected, track and playlist IDs, titles, artists, album names and playlist information. These data provide the source entries for matching and transfer.
  • Authorization information: OAuth access and refresh tokens granted by Google and Spotify, authorization state and related account or channel identifiers needed for the active connection. PlaylistBridge does not ask users to type their Google or Spotify passwords into the application.
  • Local operational data: application preferences, transfer progress, search/match caches, selected destination associations, recovery state and diagnostic logs. Diagnostic logs may contain playlist names, resource identifiers or error details associated with API requests.

For YouTube authorization, PlaylistBridge requests the scope https://www.googleapis.com/auth/youtube.force-ssl, which can permit reading and managing YouTube playlists and related resources. The application uses authorized operations to perform the playlist actions the user selects.

3. How data is processed and shared

PlaylistBridge processes playlist information on the user's Windows computer to display source entries, find candidate matches, associate source tracks with destination videos, track progress, and carry out user-requested playlist operations.

  • Google and YouTube: the application sends authorized requests to Google OAuth and YouTube Data API v3. YouTube search queries may contain song titles and artist names originating from Spotify. When the user starts a transfer, PlaylistBridge sends selected video IDs, destination playlist identifiers and playlist operations to YouTube on the user's behalf. Google and YouTube process the information they receive under their own policies.
  • Spotify: the application sends requests to Spotify's OAuth and API services to authenticate the user and retrieve the playlists and tracks requested by the user. Spotify processes the information it receives under its own policies.
  • Application developer and internal recipients: PlaylistBridge does not operate a separate publisher-hosted music-library database or a developer-operated account system. Playlist and token data normally remain on the user's computer; the developer does not automatically receive them. If a user voluntarily sends diagnostic files or other details to support, the developer receives the information included in that message or attachment and uses it to respond to the support request.
  • Other external parties: the Windows application does not send YouTube playlist data to advertising networks or data brokers and does not sell user information. The desktop application does not include a separate advertising or behavioral analytics service.

Website and releases: the public PlaylistBridge website is hosted on GitHub Pages, and the review build is distributed through GitHub Releases. When you visit those websites, their providers may process technical connection information such as your IP address and browser details under their own policies. Visiting the website is separate from sharing Spotify or YouTube playlist data through the desktop application.

4. Local storage, device technologies, and cookies

PlaylistBridge accesses and stores information on the user's device. Application configuration, authorization state, tokens, playlist-related metadata, caches, transfer mappings, logs and recovery data may be stored under %LOCALAPPDATA%\PlaylistBridge for the signed-in Windows user. The application reads and updates these files and settings as required for its features. Eligible saved credentials and tokens are protected using Windows Data Protection API (DPAPI) for the current Windows user.

Cookies and similar technologies: PlaylistBridge does not use its own cross-site advertising cookies in the Windows desktop application. The application opens Google and Spotify OAuth sign-in pages in your system browser; on these third-party pages, Google and Spotify may place, read, or recognize cookies, local storage, session storage, or similar browser identifiers to support login, account protection and consent. The browser and the website hosting providers may also store history, caching information, or site data independently of PlaylistBridge. The desktop application does not control how third parties manage their cookies. Refer to the applicable third-party privacy and cookie policies.

5. Retention, refresh, and deletion of stored information

Local search/match-cache records are intended to expire after 30 days. On application startup, PlaylistBridge removes certain expired transfer-session, search, and snapshot files older than 30 days. Some local destination associations and index records can remain during ongoing use to help resume transfers and avoid duplicate playlist creation; they are removed when the YouTube account is disconnected or the relevant local application data is deleted.

YouTube API Data: subject to the applicable exceptions in the YouTube API Services policies (including authorized tokens and certain authorized statistics), stored YouTube API Data must be refreshed or deleted within 30 calendar days, whether obtained with or without authorization. YouTube data displayed as current should be checked against the latest available information. The current build still requires further validation and correction of certain shared local association and index records to ensure this limit is enforced consistently, including during long-running sessions and before reuse. Authorization tokens are retained only as necessary for a valid, active user authorization.

Deleting locally stored data: use Disconnect YouTube in PlaylistBridge to remove the connection and its associated local YouTube data. You can also close the application, revoke its Google authorization, and remove the local application data at %LOCALAPPDATA%\PlaylistBridge; removing that directory may also erase Spotify data, preferences and transfer history. For assistance with a deletion request, contact the developer using the address below. Because PlaylistBridge does not operate a central account database, the developer generally cannot directly access or remotely erase data on your Windows device.

Deleting data stored by PlaylistBridge does not delete any playlist, video, or other content hosted by YouTube or Spotify. To delete content on those services, use their own applications or an authorized API client with the relevant capability.

6. Revocation and user controls

Users can select Disconnect YouTube to request OAuth token revocation using Google's official endpoint. When revocation succeeds, or when the saved token is already invalid, PlaylistBridge removes the locally stored YouTube token and associated YouTube data, including relevant caches, mappings, transfer state and diagnostic logs. Cleanup interrupted by an application error is retried at startup.

If Google cannot be reached, the application cannot confirm remote token revocation. Users may remove the local connection and should independently revoke the application's Google access in Google Account third-party access settings (also available through Google Account connections). Spotify authorization may be revoked through the Spotify account's application access settings.

For privacy questions, support, and deletion requests, contact fanmobilea@gmail.com. Deletion requests for data under the developer's control are handled as soon as possible and no later than seven calendar days after receiving the request, as required by YouTube API Services policies. The developer can provide instructions for locally stored data that remains under your control on your own device. If access has been revoked at Google, the application must also stop using the revoked authorization and remove associated locally stored authorized data as required by the YouTube API policies.

7. Security

OAuth sign-in takes place on official Google and Spotify pages in the system browser. PlaylistBridge does not request or retain account passwords. Local credential protection uses Windows DPAPI, and API requests use the service providers' secure endpoints. No storage or transmission method is completely risk-free.

8. Third-party policies and terms

PlaylistBridge uses YouTube API Services. By using PlaylistBridge's YouTube functionality, users are also subject to the YouTube Terms of Service. See the Google Privacy Policy for how Google processes data and the Spotify Privacy Policy for how Spotify processes data.

9. Policy updates

This policy may be updated to describe changes to PlaylistBridge's functionality, API access, data processing or retention practices. The update date at the top of this page will be revised when changes are published.

10. Contact
